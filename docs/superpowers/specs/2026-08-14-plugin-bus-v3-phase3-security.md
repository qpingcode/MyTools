# 插件消息总线 v3 三期设计：第三方插件安全与诊断

> 本文档是 v3 设计拆分后的第三期，在[第一期核心](2026-08-14-plugin-bus-v3-core.md)的 capability 骨架之上接入真实授权决策，并追加独立诊断通道。**触发条件：决定接受非本项目作者编写的插件。** 在插件全部自写可信期间，本期不实施。

## 范围

1. 面向不可信插件的威胁模型。
2. capability 授权：用户同意、发布者身份、来源绑定、授权粒度和速率限制。
3. 独立诊断管道。

## 威胁模型

所有来自 Node、WebView 和诊断连接的协议输入都视为不可信，必须做身份、路由、大小和 DTO 校验（第一期已实现结构校验，本期把语义从"防 bug"升级为"防恶意"）。但 Node 插件进程以当前 Windows 用户权限运行，可以直接访问该用户可访问的文件、网络和系统 API。因此 capability 网关提供的是统一 API、知情同意、最小授权和审计，**不是抵御恶意插件代码的操作系统安全边界**。

用户只能安装可信来源的插件。AppContainer、受限令牌、文件系统隔离和网络隔离属于后续独立沙箱设计。Job Object 只用于进程树回收，不设置资源配额，也不能被描述为安全沙箱。

XSS 页面会获得该插件 WebView 被允许的业务调用能力，因此 Node handler 必须验证业务参数和调用上下文；宿主注入的基线 CSP（第一期已实现）在本期升级为不可放宽的策略校验。

## capability 授权

第一期的"声明即授予"接口点在本期替换为真实决策：

1. 用户授权按插件包 ID、**发布者签名身份和安装来源**绑定；运行时只授予当前 entry 声明且获批的子集。
2. capability 声明扩张、发布者身份变化或安装来源变化必须重新征求同意。未签名的本地开发插件使用独立开发身份，不继承已发布插件授权。
3. capability 元数据定义持久、每会话或每次调用授权，以及调用速率限制；超出速率限制返回 `RateLimited`（区别于并发背压的 `TooManyRequests`，`retryable` 语义不同）。
4. 用户可以在宿主设置中查看并撤销授权；撤销后进行中的调用完成，后续调用返回 `CapabilityDenied`。
5. 第一期的审计日志在本期成为授权 UI 的数据来源（最近调用记录、频次）。

## 诊断连接

诊断工具使用独立命名管道，不复用插件总线管道。诊断进程必须由宿主启动或显式批准；宿主启动的进程通过 stdin bootstrap 首行获得短时一次性令牌，用户显式批准的外部工具通过宿主 UI 展示的一次性配对码换取令牌。诊断 endpoint 使用保留的 `diagnostics.*` 路由，默认只读取状态、时延、计数和脱敏错误摘要，不读取业务 payload、凭据或敏感数据。

## 测试增补

- 未声明与用户拒绝的 capability 在端到端链路上的行为
- 授权撤销的生效时机
- 速率限制与 `RateLimited` 错误
- 安全用例：WebView 冒充其他插件、未经授权的诊断连接、诊断配对码重放
- 声明扩张与发布者身份变化触发重新同意
