# 插件宿主中央消息总线设计（总览）

> 2026-08-14：原单篇设计已按实施阶段拆分为三份文档。拆分原则：**事后无法兼容更改的协议表面第一期就冻结；事后可以无重构追加的机制按触发条件推迟。** 本文只保留总览和范围划分，完整内容见各期文档；拆分前的完整单篇版本见 git 历史。

## 背景与结论

当前 Node 插件通过 stdin/stdout 逐行 JSON-RPC 与 WPF 宿主通信，WebView2 前端由具体控件转发消息，协议、UI、生命周期和宿主能力绑定较紧。目标架构为"宿主中央消息总线 + 插件会话 + capability 网关"：统一 envelope，命名管道 + WebView2 双 transport，每 entry 一个带自动重启的会话状态机，Node 重启时强制重载插件页面，宿主能力经网关调用。

第一期的信任假设是**插件全部由本项目作者编写、可信**，因此授权同意、签名身份、取消传播、订阅过滤和完整背压模型均按触发条件推迟，但协议表面（envelope 字段集、握手 bootstrap 契约、路由命名空间、at-most-once 语义）在第一期冻结，保留 route 名给后续阶段。

## 跨阶段不变量

以下决定在第一期做出并对所有阶段有效：

1. 已有 envelope 字段的名称、类型和语义冻结；新增仅限可选字段并经次版本协商，旧端忽略未知字段。
2. 握手是永久冻结的 bootstrap 契约，任何版本都能解析并回应 `ProtocolMismatch`。
3. 交付语义 at-most-once：不重放、不持久化、断线不自动重试。
4. 宿主不信任入站身份字段，由 transport 按已认证绑定规范化。
5. `plugin.call.*` / `plugin.event.*` 的 payload 对总线不透明，插件业务 Schema 属于插件内部实现。
6. WebView 不能直接调用 `host.call.*`；系统能力必须经 Node 到 capability 网关。
7. 主 Node 重启即强制重载该 entry 的插件页面，页面状态与 Node 状态始终同代。
8. capability 网关的架构位置和"每次调用校验声明与 DTO"在第一期即为最终形态，三期只替换授权决策的实现。
9. 操作系统级沙箱（AppContainer、受限令牌）不属于任何一期，单独设计。
10. 旧 stdio 协议整体替换、不长期并存。
