# API 开发测试插件需求说明

## 1. 目标与首期范围

在 MyTools 中提供轻量的 HTTP/HTTPS API 调试与简单测试工具，形成“编辑请求 → 发送调试 → 保存复用 → 简单验证”的流程。

典型场景：保存登录和用户信息请求，选择环境，提取登录令牌供后续请求引用，按顺序运行集合，在界面查看响应和断言结果。

首期只包含下文要求。不包含导入导出（含 cURL）、测试报告、JavaScript 脚本、动态变量、多轮迭代、请求间隔、全局或集合变量、认证继承、文件夹、拖动排序、历史记录、异常草稿恢复、说明字段、Cookie 管理界面、XML 格式化、JSON 折叠与字段搜索。团队协作、云同步、Mock、其他协议及压力测试也不在首期范围内。

## 2. 工作区与保存

- 提供独立插件入口，遵循 MyTools 的主题、语言和交互规范。
- 左侧展示集合与环境，编辑区配置请求，响应区展示响应和测试结果；提供新建请求入口。
- 支持多个请求标签页；切换时保留编辑内容及最近响应。未保存变更明显标识，关闭标签页或正常退出时提供保存、放弃和取消操作。
- 集合直接包含请求，支持集合和请求的新建、重命名、删除、复制，按名称或 URL 搜索请求；请求用上移、下移调整顺序。删除集合前提示包含的请求数量。
- 区分临时请求与已保存请求，提供显式保存。保存包括请求配置、文件引用、执行设置覆盖、断言和提取配置，不保存响应或批量结果。
- 重启后已保存的集合、请求顺序及环境配置保持一致；未保存编辑、响应、临时变量和 Cookie 不恢复。

## 3. 请求构造与执行

### 3.1 URL、参数与请求头

- 支持 GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS，以及完整 HTTP/HTTPS URL。
- URL、查询参数、请求头、认证及文本正文支持 `{{变量名}}` 引用；发送前校验协议、URL、未定义变量和最终正文，错误定位到字段。
- 查询参数和请求头使用键值表，支持添加、删除、启用、禁用。查询参数支持空值、重复名称并保留顺序。
- 参数表编辑原始值，发送时编码一次；解析 URL 查询部分时先解码，字面 `+` 保持加号。原始 `%2F`、`+`、空格分别发送为 `%252F`、`%2B`、`%20`。保留 `flag` 与 `flag=` 的区别。
- 参数表修改同步到 URL；直接修改 URL 时替换参数表，若会丢失禁用项则先提示并允许取消。
- 区分并展示手工及自动生成的请求头。认证配置与启用的同名手工头或参数冲突时阻止发送；头名称不区分大小写，参数名称区分大小写。
- Content-Length 和 Multipart 的整体 Content-Type、boundary 由执行器生成，不允许手工覆盖。JSON 默认使用 application/json；JSON 与原始文本允许手工设置 Content-Type，不符合正文默认类型时提示但允许发送。

### 3.2 请求体与认证

| 请求体 | 要求 |
|---|---|
| 无正文 | 不发送正文 |
| JSON | 编辑、格式化和语法校验 |
| 原始文本 | 支持文本、XML 等，自定义 Content-Type |
| URL 编码表单 | 键值编辑、重复字段，原始值编码一次 |
| Multipart 表单 | 文本、单文件、多文件，配置字段名及字段 Content-Type |
| 二进制文件 | 选定文件作为完整正文 |

文件显示名称、类型和大小，保存时只存引用；发送前检查是否存在且可读取，失效时提示重新选择。上传可取消，不阻塞界面。

每个请求单独配置无认证、Basic Auth、Bearer Token 或 API Key（请求头或查询参数），不继承集合认证。

### 3.3 执行设置

- 超时默认 30 秒，覆盖连接、重定向和完整正文接收。
- 默认自动跟随重定向，最多 10 次，超限报错。
- 可设置是否校验 TLS 证书，默认开启。
- 上述设置支持全局默认和请求级覆盖，覆盖随请求保存。
- 自动接收和发送 Cookie，按目标域、路径等属性匹配；手动调试按环境隔离并在会话内共享，“无环境”使用独立容器。每次批量运行使用新的独立容器，不与手动调试共享、不写回。提供清除当前容器操作，不提供 Cookie 编辑管理界面，不跨重启保存。
- 单次请求和批量运行均显示运行状态、允许取消，并及时释放网络和文件资源。

## 4. 响应展示

- 展示状态码、总耗时、正文大小、实际请求 URL、完成时间及断言通过/失败数量。耗时从开始发送到正文接收完成，不含断言、提取和界面渲染；大小按解压后、字符解码前的正文字节数计量。
- 文本提供原始视图，JSON 额外提供格式化视图；格式化失败保留原文并提示原因。支持复制正文及响应头，完整正文可保存到文件，二进制响应提供保存操作。
- 响应头以表格展示并保留重复字段；不额外提供 Cookie 属性查看器。
- 预览上限 1 MiB，完整正文接收及测试处理上限 20 MiB，按解压后的字节数计算。仅预览超限不影响完整正文的断言、提取或保存；接收超限则终止接收并明确报错，保留摘要及响应头，不用截断正文测试或冒充完整文件保存。
- 区分配置错误、DNS/连接失败、TLS 校验失败、超时、取消、解码失败、正文超限、重定向超限及提取失败。HTTP 4xx、5xx 是有效响应，保留其头与正文。
- HTML 作为原始文本展示。

## 5. 环境与变量提取

- 环境支持新建、复制、重命名、删除和切换，也支持无环境状态。变量配置包含名称和字符串值。
- 只有环境变量和临时运行变量，优先级为 **临时运行变量 > 环境变量**。空字符串有效，未定义变量阻止发送；不递归解析变量值中的引用，不替换二进制文件内容。
- JSON 正文按文本替换后校验，不自动补引号或转义；用户需填写符合插入位置的 JSON 文本。
- 手动调试各标签页共享当前环境的临时变量，登录提取的令牌可用于后续手动请求；切换环境或重启插件时清空，切回旧环境不恢复。
- 每次批量运行从空临时变量开始，只在本批次内共享，结束后丢弃，不读取或写回手动调试临时变量，也不写回环境。
- 批量启动时固定所选请求、顺序及环境变量快照，运行期间编辑或切换环境不影响当前批次。手动发送同样固定启动上下文，旧环境中的在途请求不得向切换后的会话写入变量。

JSON 提取配置包含启用状态、JSON Pointer 路径和目标变量名。例如将 `/token` 提取到 `token`，后续引用 `{{token}}`。空路径表示根值，`~0` 表示 `~`、`~1` 表示 `/`，不支持通配符；缺失字段与 null 区分，无效 JSON 或缺失路径导致提取失败。字符串直接保存，其他 JSON 值序列化为字符串。

执行顺序为：**固定上下文 → 解析与校验 → 发送并接收完整响应 → 全部断言 → 全部提取 → 汇总**。断言失败仍执行其余断言和提取；当前请求的提取全部成功才提交临时变量，任一提取失败则全部丢弃，保留此前请求的变量。同名提取按配置顺序最后写入生效。取消或没有完整响应时不执行断言和提取。

## 6. 简单测试与批量运行

### 6.1 可视化断言

| 类型 | 条件 |
|---|---|
| 状态码 | 等于预期值 |
| 响应时间 | 小于阈值 |
| 响应头 | 存在指定头 |
| 文本 | 包含指定文本 |
| JSON 字段 | JSON Pointer 路径存在 |
| JSON 值 | 等于预期值 |
| JSON 类型 | 符合指定类型 |

每条断言包含名称、启用状态及对应条件，结果显示实际值、预期值和失败原因。JSON 值按严格类型深比较，数组顺序有效、对象字段顺序无关，数字不等于数字字符串；null 字段仍视为存在。头名称不区分大小写，文本包含区分大小写。

### 6.2 批量运行与结果

- 可运行整个集合或所选请求，按集合顺序执行一轮，不并发、不设置间隔。
- 选择环境及失败后继续或停止，默认继续。配置、执行、提取错误或断言失败均触发停止策略；停止结束整个批次，剩余项跳过。
- 取消时正在处理的请求标为取消，未开始项标为跳过；已完成的项保留结果。
- 界面显示总进度、当前请求、总时长，各请求状态码、耗时、断言和失败原因；结果仅保留在当前会话，不生成报告或历史。

| 维度 | 状态定义 |
|---|---|
| 请求执行 | 完成：收到完整响应，包括 4xx、5xx；执行失败：配置或接收等错误导致未完成；取消：处理期间被取消；跳过：未开始 |
| 测试结果 | 通过：至少执行一条断言且全部通过、无其他错误；失败：配置、执行、提取错误或断言失败；未测试：请求完成、无错误且没有启用断言；不适用：取消或跳过 |

请求执行四种状态互斥，计数之和等于所选请求总数；进度按已处理及跳过数量计算。测试与断言计数独立展示。HTTP 500 无断言且无其他错误为“完成、未测试”；HTTP 200 断言失败为“完成、测试失败”。

## 7. 基础约束

- 配置保存到本地，避免半写入，升级兼容已有保存数据。
- 网络、正文处理和测试不阻塞主界面，单个请求异常不导致宿主崩溃。正文受上述容量限制，标签页与批量结果采用有界缓存，不能无限积累完整响应。
- 支持键盘操作和清晰焦点，状态不只靠颜色表达。
- 所有用户可见文本遵循仓库本地化规范：Node/Web 使用插件 JSON/i18next 并覆盖声明的语言；Desktop/WPF 使用 RESX，覆盖英文、zh-CN、fr-FR。
- 实现中的默认值和限额使用具名常量，离散状态使用枚举，遵循仓库无魔法字符串或数字要求。

## 8. 首期验收

| 项目 | 验收条件 |
|---|---|
| 请求构造 | HTTP 方法、参数、头、四种认证及各正文类型可用；编码、重复项和认证冲突处理符合约定 |
| 文件上传 | Multipart 单/多文件与二进制上传可用；文件失效明确提示，上传可取消 |
| 执行设置 | 30 秒默认超时、10 次重定向上限及 TLS 校验开关生效，请求覆盖可保存；Cookie 隔离和清除可用 |
| 响应与异常 | 摘要、原文、JSON 格式化、复制和正文保存可用；4xx/5xx 正常展示，各类错误及取消可区分 |
| 集合与保存 | 显式保存并重启后请求、顺序和环境一致；标签切换保留编辑，关闭时有未保存提示 |
| 变量与关联 | 环境切换、优先级、未定义变量和 JSON 替换校验正确；登录提取可跨标签引用，批量变量独立且结束后丢弃 |
| 断言与提取 | 七种断言、JSON Pointer、严格类型比较及 null/缺失区分可用；断言失败仍提取，提取失败不提交当前请求的任何变量 |
| 批量结果 | 单轮顺序、部分选择、停止与取消可用；执行、测试和断言统计符合定义，失败原因可定位 |
| 资源与稳定性 | 1 MiB 预览限制和 20 MiB 接收限制生效，不测试截断正文、不阻塞宿主 |
| 国际化与操作 | 所有用户可见文本覆盖对应语言，键盘可操作且状态不依赖颜色 |

## 9. 开发顺序

1. 请求编辑、认证、上传、响应展示、执行设置与取消，完成单接口调试。
2. 集合、本地保存与环境变量，完成请求复用。
3. 可视化断言、响应提取、单轮批量运行及界面结果，完成简单测试闭环。

首期正式版完成以上三步，不以暂缓功能作为验收前提。
